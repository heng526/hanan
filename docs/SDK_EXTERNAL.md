# SDK 外部准备与版本边界

厂商 SDK 由设备提供方单独交付并按其许可使用；本仓库没有重新分发 SDK 头文件、示例或库。公开的 C++ 文件是自有调用桥接。不要从本仓库安装脚本推断设备已验收。

选定路线为 X86 高层 TCP 301。指南 X86 链接实际指向 `high_level_remote_client_301 1.zip`；无空格的同名包为 ARM64。301 的库位于 `build/libhigh_level_remote_tcp_client.so`，指南建议 Ubuntu 20.04；客户端版本须与设备服务端匹配。实际运行 `GetSdkVersion` 尚未核验。

当前 `CMakeLists.txt` 与桥接仍面向 v5.0.4 Fast DDS 的 `lib/libCrobotcontroller.so`。桥接引用的 `GetGpsLocation` 不在 301 头文件中，两个版本的电机温度数组长度也有差异。因此不能仅把 SDK_DIR 指向 301 后直接复用构建。请先在私有开发环境取得对应架构与服务端版本的合法 SDK，再完成单独的构建路径和 API 兼容适配；本次发布未编译或导入厂商库。

301 示例以返回码 0 打印 SUCCESS；`GetActionStatus` 只打印整数。公开头文件与示例没有定义逐命令 accepted/command_id/timestamp、完成状态枚举或取消确认。`StopMove` 返回码不能单独证明实体停稳。`GetRobotSpeed` 的 body_x/y/z/ang 和里程计线/角速度可供后续观测接入，但这些结构未提供采样时间、有效性或序号。

底盘状态与排风/摘管上装回执分别对接。框架 `nav/action_receipt.py` 要求当前命令 ID 与时间戳；不能用底盘全局整数状态替代上装逐命令回执。

## 最小资料清单

1. 实际固件/服务端与 301 客户端的兼容版本；返回码、动作状态整数含义、停止/失联语义。SDK 已取得时无需再次索取包。
2. 前后 RGB 是否另有深度、输出分辨率/格式与深度单位、对齐方式；用于三维定位时提供对应分辨率内参和畸变、相机到机体的外参。
3. 雷达型号、2D/3D、量程/视场/盲区/更新率、雷达到机体外参；仅进行相机雷达融合时需要两者关联变换。
4. 现有驱动/消息字段/坐标轴/单位/时间戳时钟与延迟说明，及一段同步样例（RGB/深度/雷达/位姿）。硬件同步仅在精度要求确有需要时追加。

内参把像素和深度转换成空间位置；外参把位置与方向转换到机体；时间对齐保证各传感器描述同一时刻。普通图传不能自动提供深度与标定。仅做图像显示无需一次索取全部标定参数。
